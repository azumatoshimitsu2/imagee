# 自分自身と議論するゲーム — 開発・テスト

本体はHTML / CSS / JavaScript（ES Modules）/ localStorage。ユーザーの方針変更により、画面層だけLitを使用する。TypeScript・ビルド工程は導入しない。ブラウザテストはPlaywrightを開発依存として使用する。Ajvは導入しない。

公開対象は `../../dist/games/d/what_would_you_do/`。このディレクトリのnpm依存や設定は公開サイトで読み込まない。Node.jsの標準テストでデータ・ロジックを検証し、Playwrightで実ブラウザの動作を確認する。

## 画面と処理の境界

- UIは `../../dist/games/d/what_would_you_do/js/ui/` に配置し、`../vendor/lit.js` からLitを読み込む。
- Lit 3.3.3の公式ビルド済みcoreをサイト内に同梱する。閲覧時のCDNアクセス、npm install、ビルドは不要。出典・ハッシュ・ライセンスはvendor/lit/に記録する。
- Storage、Scoring、Comment、Question、Profileの各Engineは通常のJavaScriptで実装し、LitやDOMへ依存させない。
- UIはプロパティで表示データを受け取り、イベントで操作を通知する。UIからlocalStorageを直接操作しない。
- 通常のJavaScriptクラスとstatic propertiesを使い、TypeScriptの型・デコレータは使わない。
- 自由記述は仕様どおりtextContentで出力する。unsafeHTML、unsafeSVG、ユーザー入力からのテンプレート生成は禁止。質問・ルールのJSON形式は変更しない。
- 実装順序はStorage→Scoring→Comment→テスト→Question→LitのUI→Profile/Historyのままとする。

## セットアップ

Node.js 22以降の対応版、npm、Python 3を用意し、このディレクトリで実行する。

```sh
npm ci
npx playwright install chromium
npm test
```

- `npm run test:data`: データ定義の整合性
- `npm run test:logic`: 保存・履歴・採点・発見・出題の処理
- `npm run test:browser`: デスクトップとスマートフォン相当のChromium
- `npm run test:browser:headed`: ブラウザを表示して実行

Playwrightはテスト中だけ127.0.0.1:8773でdistを配信し、終了時にサーバーを停止する。ポートが使われている場合は、既存サーバーを流用せずエラーにする。

現在のブラウザテストはJSON読み込み、日本語の確認、同梱Litの読み込み・表示更新・文字列の安全な表示を対象とする。Storageと各Engineを実装済み。実localStorageの保存・変更履歴・再読み込み・JSON入出力・破損データ保持・自由記述の安全な表示も検証する。ホーム、質問・回答後、履歴、データ管理の画面を接続済み。ブラウザテストは、実際のラジオボタン・送信・履歴からの再回答・理由のスキップ・自由記述・データ復元も対象とする。モバイル設定は画面・入力のエミュレーションであり、実機Safariの検証ではない。

仕様とデータの編集方法: `../../dist/games/d/what_would_you_do/data/README.md`。

Playwright公式: https://playwright.dev/docs/intro

処理のAPIと未確定条件: `../../dist/games/d/what_would_you_do/js/ENGINES.md`。

## 最小画面

`/games/d/what_would_you_do/` を開く。公開サイトに追加のビルドは不要。

- `#home`: 次の未回答の問いと、時間を置いた振り返りの案内
- `#rest`: 回答を保存したままひと休みする案内
- `#archive`: ほかの未回答の問い（後日・件数条件を適用）
- `#question`: 本文と選択肢、履歴からの再回答
- `#answer`: 任意の理由・自由記述→解説→関連する過去回答との対話
- `#profile`: 6軸の地図、件数に応じた非表示／暫定表示、根拠回答へのリンク
- `#history`: 現在の回答、当時の理由・文章、以前の回答、解説の再読
- `#about`: 説明、JSON書き出し／読込、確認後の全削除

画面はLitのLight DOMで構成し、共通CSSを適用。plain-text要素は保存済み文章をtextContentで出力する。画面遷移で見出しへフォーカスし、選択肢はネイティブのradio/fieldsetを使用する。

元のひな型にあったGoogle Tag Managerと共通サイトスクリプトは読み込まない。回答データは外部送信せず、Litも同一サイト内から取得する。心象風景は「あなたの地図」に接続済み。画像と定義は画面を開いたときに取得し、人格の断定を避けて根拠回答へ戻れるようにしている。質問は引き続きレビュー草案として読み込んでいる。

「あなたの地図」はProfile Engineのvisibilityを尊重し、3件未満の軸や全体5問未満では位置を描画しない。明示関係からの発見は最大1件を表示し、閲覧だけでは発見履歴を書き換えない。カテゴリ差・時間差の高度な分析は引き続き保留。

`#past` は「過去の自分」画面です。履歴中の回答（変更前を含む）・自由記述を選び、今の気持ちと任意の文章を返せます。返事は別履歴として保存され、JSON の書き出し・読み込み・削除にも含まれます。Playwright の `past.spec.js` で空状態、変更前の回答への返事、再読み込み、自由記述、キーボード操作、HTML の文字表示を確認します。

`#compare` は「二つの答えを見比べる」画面です。「過去の自分」のリンク、地図上の発見、回答後の関連コメントから開けます。既存ルールの回答数条件を満たした組み合わせを比較し、当時の理由・言葉とともに振り返れます。`comparison.spec.js` は空状態、地図からの移動、理由表示、任意の文章、再読み込み、変更前の回答の保持、JSON復元、キーボード操作、安全な文字表示を検証します。

`#boundary` は条件を変えて考える画面です。「過去の自分」「あなたの地図」から開けます。最初の題材は手伝いによる予定の遅れ（5・30・120分）。`boundary.spec.js` が中断・再読み込み・三条件の完了・境界からの振り返り保存・同じ選択・決められない選択を検証します。処理テストでは非単調な回答や質問version変更も確認します。

`#revisit` は「同じ問いに、もう一度」画面です。「過去の自分」から、以前の答えを見る前に問いを選べます。任意の理由とともに答えた後、以前と今回の回答・理由・日時を比較し、気づきを残せます。`reevaluation.spec.js` は回答前の非表示、同じ答えで異なる理由、再回答の変化、保存と再読み込み、以前の比較の保持、古い回答URLでの再送信防止、キーボード操作と安全な文字表示を確認します。

`#words` は「言葉の足あと」画面です。「過去の自分」から開き、同じ問いに残した自由記述・以前の返事・今の文章を古い順に読み返せます。`words.spec.js` で空状態、既存の返事の表示、追記・再読み込み・JSON復元、キーボード操作と安全な文字表示を確認します。処理テストでは質問versionごとの分離、元記録の保持、分析への非影響も確認します。

ホームの「今日、振り返る一つ」は7日以上前の記録から1件を案内します。見送りは保存され、その日の別提案は出しません。`daily-reflection.spec.js` で選択内容を隠したカード、日ごとの固定、見送りと再読み込み、日付変更、再回答と自由記述への移動を確認します。処理テストは日数境界、優先種別、再提案間隔、件数設定、元回答の変更、JSON復元、履歴保護、スコアへの非影響を検証します。

`#past` は五つの振り返り方を選ぶ入口です。個別の記録一覧は `#past?view=records` に移しました。保存済みの返事・比較・途中の条件・再回答・自由記述から再開リンクを組み立てるため、専用の進捗保存は不要です。未保存の入力の復元は行いません。`reflection-hub.spec.js` は空状態の五つの入口、保存済み記録への再開、再回答の内容を入口に表示しないこと、読み返しだけでは保存データを変えないことを確認します。

心象風景の定義は `data/landscapes.json`、純粋な選定処理は `js/landscape-engine.js`、表示は `js/ui/landscape-view.js`。`landscape.spec.js`で遅延読み込み、画像・JSONの取得失敗、再試行、根拠の閲覧、回答変更、安全な文字出力を確認する。
